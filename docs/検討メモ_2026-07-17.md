# 同人誌(エロ系)量産 検討メモ 2026-07-17

## 目的
AI活用でエロ同人誌の量産パイプラインを構築できないか検討開始。

## 全体工程イメージ
```
①企画・台本      → LLM（Claude/ChatGPT）
②キャラ設定・絵作り → ComfyUI or Draw Things（Stable Diffusion系）
③漫画の組版       → Clip Studio Paint（吹き出しはPythonスクリプトで自動化余地あり）
④出品・販売       → DLsite / FANZA同人
```

## 販売先
- DLsite / FANZA同人が候補。年齢確認・決済・DL配信をプラットフォーム側が担保してくれるので運用しやすい
- コミケ等の即売会は成人向け持ち込みルールが厳格 → 電子販売オンリーの方が量産と相性良い

## 絶対条件（一線）
- キャラは必ず成人と明確にわかる設定にする（体型・年齢設定・文脈すべて保守的に）
- オリジナルキャラ vs 二次創作は要検討（二次創作は著作権リスクあり、オリジナルの方が長期スケールしやすい）

## 環境
- Mac: Apple M5 / 16GB RAM（Apple Silicon, arm64）
- Homebrew: 未導入（要ターミナルで手動インストール、sudo入力が要るため自動化不可）
- git / python3.9.6 は既存

## ツール比較（絵作り工程）
| | ComfyUI | Draw Things |
|---|---|---|
| 導入コスト | 高い（Homebrew→Python env→モデル導入） | 低い（App Store、GUIで完結） |
| 向いてる場面 | バッチ量産・ワークフロー自動化 | まず1枚試したい・感触を掴みたい |

## 自動化難易度の整理
| 工程 | 難易度 |
|---|---|
| 台本・セリフ生成 | 簡単（LLMで完全自動化可） |
| キャラ差分生成（ComfyUI） | 自動化可（LoRA＋バッチ） |
| 絵の破綻修正（手など） | 難しい（人力必須、現状） |
| 吹き出し配置・文字組み | 簡単（先に空白確保→Pythonスクリプトで自動流し込み可能） |
| コマ割り設計 | 中（テンプレ運用で対応） |
| 規約適合の最終判断（DLsite/FANZA） | 人力必須 |

→ 完全ゼロ人力の自動化は現状困難。「AIが8〜9割、人が最終チェックのみ」の半自動ラインが現実的な落とし所。

## 追記 2026-07-17（深掘りリサーチ後）

### 自動化の軸：NovelAI API → ComfyUI自体のAPIに方針転換
- NovelAI用の非公式Python SDK（Aedial/novelai-api、LlmKira/novelai-python等）は軒並みメンテ停止・アーカイブ済みで、量産自動化の基盤には不向きと判明
- ComfyUIはローカルに自分専用APIサーバー（`http://127.0.0.1:8188`）が立つので、非公式ラッパーに頼らずPythonから直接ワークフローJSONをPOSTできる。こちらの方が信頼性が高い

### ほぼ自動化パイプラインの現実的な形
```
①台本・コマ割り生成 → LLM → 完全自動
②画像バッチ生成    → ComfyUI API直叩き → 完全自動
③顔の自動補正      → Face Detailerノード → 完全自動（精度は不完全）
④モザイク処理      → センシティブ部位自動検出ワークフローが個人配布されている（pipix氏配布）→ 自動化可
⑤吹き出し・セリフ   → Pythonスクリプト(Pillow) → 完全自動
⑥最終チェック      → 人力（破綻・規約適合の確認）← ここだけ残る
⑦出品            → DLsite/FANZA手動アップロード
```

### 追記4 2026-07-17（制作手順の最適化リサーチ）

**技術的な自動化の中身（確定）**
- ComfyUIは`http://127.0.0.1:8188/prompt`にJSONをPOSTするだけのローカルAPI。`comfy_api_simplified`というPythonライブラリでパラメータ差し替え＋キュー投入が可能
- 標準Queue機能は50〜100枚が実用上限、1000枚規模はAPI自動化必須（CSV/JSONにプロンプト一覧を書いて読み込ませる）
- 生成→アップスケール→顔修正→パース補正を1本のワークフローに統合すると、Automatic1111比で1ページ約40%速いという報告
- ステップ数20〜30が標準、シンプルな絵なら12でも可（速度と画質のトレードオフ）
- プロンプトは「色→服装→ポーズ→背景→構図→光源→感情」の順で型化、コマ割りは4コマ/見開き/起承転結のプリセット活用が定石

**⚠️重要な反面教師（ゆん・コヒヤ氏の実体験）**
- LoRA作成・配合調整だけで1ヶ月かかり、「フルカラー40P/8週間」＝過去の「手描きモノクロ52P/2ヶ月」より遅くなった実例あり
- 原因：「AIの汎用的な美麗さでは満足できず、自分の『こだわり』をAIに叩き込む作業」に膨大な時間がかかった
- 教訓：自動化は「絵を描く時間」を消すだけで、「理想に近づける時間」はLoRA調整・プロンプト設計に移動するだけ。**1作目はテンプレート/LoRA構築に時間がかかる前提で計画し、量産効果は2作目以降から**という想定にする

**メモリ状況（要注意）**
- Mac全体で16GB中15GB使用、空き87MB程度とかなりギリギリ。他アプリ（ブラウザ多タブ等）と同時使用時は重くなりやすい
- 費用は一切発生していない（Homebrew/Python/ComfyUI/モデル全て無料、クラウドGPUもNovelAI課金も未使用）

**ユーザーが実際に生成に成功**
- ComfyUIのGUI（テンプレート「SDXLシンプル」、Base+Refiner構成）でBaseのみ有効化し、直接プロンプトを入力して4コマ構成のエロ漫画風画像を生成
- **重要な技術発見**：ポジティブプロンプト内に`=== Panel 1 ===`のような区切り文字でコマごとの指示を書くと、Illustrious系モデルが複数コマレイアウトを1枚の中にある程度再現できることが判明（想定より高精度）
- ただし**日本語テキスト（吹き出し内のセリフ）は文字化けする**ことを確認 → これは想定通りの制限

**日本語テキスト対応の追加調査**
- Qwen-Image/Z-Image系は日本語テキスト描写に強いが、**ベースモデルにNSFW制限が強く、NSFW LoRAを乗せてもベースモデルと「戦う」形になり機能しない**ことが判明。日本語対応と引き換えにNSFW表現を失うトレードオフがあるため不採用
- SD3ですら日本語入力が中国語風になる、など業界全体で日本語テキスト描写は未解決の課題
- **結論：モデルを乗り換えるのではなく、Illustriousで絵だけ生成し、テキスト(吹き出し・セリフ)は別工程(Pillow/専用ツール)で後付けする方針を継続**

**次回やること**
1. 空の吹き出し枠のみ生成→Pythonスクリプト(Pillow)で日本語テキストを後から合成する仕組みを作る
2. パネル区切りプロンプト技法の再現性を複数シーンで検証

### 追記9 2026-07-17（100ページ規模と判明→方針転換）

**規模感の確認：目標は100ページ級**
- 想定より大規模。100ページ×選別込みで数千枚単位の生成が必要になる見込み
- M5ローカル(1枚80秒)で計算すると、1000枚で約22時間、3000枚で約67時間 → **物理的に非現実的**
- この規模だと、レベル1(プロンプト使い回し)では一貫性のブレが蓄積するため、**LoRA学習がほぼ必須**という結論

**キャラ統一の3段階（整理）**
1. プロンプトの外見タグを毎回使い回す（今すぐ可・追加設定不要、ブレは残る）
2. IP-Adapter（ComfyUIにノード追加、ローカルで完結、参考画像に似せて生成）
3. LoRA学習（精度最高、Mac単体では不可・クラウドGPU必須）

→ 100ページ規模なら②③、特に③が必要という判断に至った

**結論：クラウドGPU(RunPod)への全面移行を検討フェーズへ**

**RunPod料金（2026年最新）**
- RTX4090：Community Cloudで**$0.34/時間**（約50円/時間）、秒単位課金、月額固定費なし
- 新規登録で約$10分の無料クレジットあり
- 見積もり：LoRA学習(1〜3h)＋バッチ生成(数時間)＝合計10〜20時間程度 →**1作品あたり約1,000〜2,000円程度**の見込み
- 注意点：Pod停止(Stop)だけだとストレージ保管料が発生し続ける。使い終わったら「Terminate(削除)」まで行うこと

**現在地**：RunPodアカウント作成・環境構築はまだこれから。ユーザーは一旦区切りをつけて、また後日試す予定。
